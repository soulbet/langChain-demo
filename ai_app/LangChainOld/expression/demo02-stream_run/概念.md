- 使用模型处理问题，响应时间过长，通过流式输出，显示中间进度

# 流式事件
> 流事件的本质是：把 AI 的内部执行过程，拆解成一个个可读的事件，实时推送给前端。
- 流事件工作流程：
- [思考中] 用户想知道北京天气，需要调用 get_weather 工具
  - [调用工具] get_weather(city="北京")
  - [工具返回] 温度 25°C，晴
  - [回答] 北京今天 25°C，天气晴朗
## 事件类型
- on_chat_model_start	LLM   开始调用	      显示"正在思考..."
- on_chat_model_stream	  LLM 输出 token	  逐字显示回答内容
- on_chat_model_end	      LLM 调用完成	  收起加载状态
- on_tool_start	          开始调用工具	  显示"正在查询天气..."
- on_tool_end	              工具调用完成	  显示工具返回结果
- on_chain_start/end	      链/节点开始/结束	  追踪 Agent 步骤
## 投影
> LangChain v3 引入了投影的概念，可以直接订阅想要的内容，不用自己解析原始事件流
- stream.messages  	获取 LLM 输出的消息流
- message.text	    获取文本内容（逐字）
- message.reasoning	获取推理/思考 token
- message.toolCalls	获取工具调用参数
- stream.toolCalls	获取工具执行生命周期
- stream.subgraphs	获取子 Agent 的执行情况
- stream.values	    获取 Agent 状态快照
## 通道和命名空间
当 Agent 很复杂（比如有多个子 Agent 并行工作）时，需要区分事件来自哪里：

通道：描述事件类型（messages、tools、values 等）

命名空间：描述事件来源（哪个子 Agent、哪个节点）

## 过滤事件
- 按名称
  model.with_config({"run_name": "model"})，参数：include_names
- 按类型
  参数：include_types
  - "chat_model"	大模型调用相关	on_chat_model_start；on_chat_model_stream；on_chat_model_end
  - "llm"	传统LLM（非chat模型）	on_llm_start, on_llm_stream, on_llm_end
  - "tool"	工具调用	on_tool_start, on_tool_end
  - "chain"	链/节点执行	on_chain_start, on_chain_end
  - "retriever"	检索器	on_retriever_start, on_retriever_end
  - "parser"	解析器	on_parser_start, on_parser_end
  - "prompt"	提示词模板	on_prompt_start, on_prompt_end
- 标签
  JsonOutputParser()).with_config({"tags": ["my_chain"]}，参数：include_tags

## 传播回调
> 让回调函数（如 on_llm_end、on_chain_start）自动传递到链中的所有子组件
### 可运行对象
> 让普通函数能参与到 LangChain 的链式调用中（支持 | 管道操作）`runnable = RunnableLambda(my_function)`

## @tool @chain
- @tool：把普通函数变成 Agent 能调用的工具
- @chain：把普通函数变成能参与 | 管道操作的链
